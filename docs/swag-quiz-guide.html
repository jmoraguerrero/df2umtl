🎁 Swag Quiz — Guide

How the quiz works, and how to add, remove, and configure questions & prizes

In one sentence: after the agent shows a customer their offer, the customer can play a short quiz; the agent asks your questions one at a time, adds up the score of each answer they pick, and awards the swag whose score band contains the total — recording one result per customer so they can’t retake it.

1. How the quiz works

The quiz is agent-conversational — it happens entirely in chat. But the agent does not make up the questions. On every turn, the agent calls an Apex action (Record Swag Answer → SwagQuizAnswer / SwagQuizService), passing the customer’s contact id and their latest message. Apex is the “brain”: it stores progress, decides the next question, scores the answers, and picks the prize. The agent only presents the text Apex returns, in a warm, natural voice.

Customer “What swag can I win?”
→
Agent calls Apex with the message
→
Apex records answer, returns next question (or result)
→
Agent presents it naturally

Because Apex drives the flow, questions always come from your data, appear one at a time (“Question 2 of 3”), and the scoring is deterministic and reliable. The customer can type the option text (e.g. Streaming & movies) or just a number (1).

2. The data model (3 objects)

Everything is configured with records in three custom objects. No code changes are needed to change the quiz content.

Swag_Question__c the questions

FieldTypeWhat it does
NameTextInternal label for the question (not shown to the customer).
Question_Text__cLong TextThe question the agent asks, word for word.
Order__cNumberSequence — 1 is asked first, then 2, 3…
Options__cLong Text (JSON)The answer choices and their scores (see below).
Active__cCheckboxOnly checked questions are included in the quiz.

Swag__c the prizes

FieldTypeWhat it does
NameTextThe swag name shown to the customer.
Description__cLong TextA short, fun description read out when awarding it.
Emoji__cTextOptional emoji shown next to the prize.
Min_Score__cNumberLowest total score (inclusive) that wins this swag.
Max_Score__cNumberHighest total score (inclusive) that wins this swag.
Active__cCheckboxOnly checked swags can be awarded.

Swag_Response__c one result per customer — managed automatically

You don’t create these; the quiz engine writes them. Useful for reporting and for the “no retake” rule.

FieldWhat it stores
Contact__cThe customer who took the quiz (one record per contact).
Completed__cChecked once finished — this is the “already played” flag that blocks retakes.
Total_Score__cThe summed score of all their answers.
Assigned_Swag__cThe swag they won.
Answers__cJSON of each answer (question, chosen label, score).
Completed_Date__cWhen they finished.

3. How scoring & matching works

  1. Each option a customer can pick has a score (a number you choose).
  2. As they answer, the engine adds up the scores of the options they selected.
  3. When the last question is answered, it computes the total score.
  4. It awards the active Swag whose band satisfies Min_Score__c ≤ total ≤ Max_Score__c. If several match, the one with the highest Min_Score__c wins.
Design tip: work out the lowest and highest possible totals first. Lowest = sum of the smallest option score on every question; highest = sum of the largest. Then make sure your swag bands cover that whole range with no gaps or overlaps.

4. Add / edit / remove questions

The Options__c format

Options are a JSON array of objects, each with a label (what the customer sees) and a score (a whole number):

[
  {"label": "Streaming & movies", "score": 3},
  {"label": "Gaming",            "score": 3},
  {"label": "Social media",      "score": 2},
  {"label": "Work & email",      "score": 1}
]
The JSON must be valid: straight double quotes " (not curly “smart” quotes), a comma between items, and no trailing comma after the last one. Invalid JSON means the question has no selectable options.

Option A — Edit records in Salesforce (easiest, no deploy)

  1. In Setup, open the Swag Question object’s tab/list (or use App Builder / a report).
  2. Add: create a new Swag Question record. Set Question_Text__c, give it the next Order__c number, paste the Options__c JSON, and check Active__c.
  3. Edit: open an existing question and change its text, options, or order.
  4. Remove: either uncheck Active__c (recommended — keeps history) or delete the record.

Changes take effect on the next quiz turn — no publish or deploy needed, because questions are plain data.

Option B — Edit the seed script (repeatable / version-controlled)

The demo content lives in scripts/apex/seed_swag.apex. Edit the questions list, then re-run it. It is idempotent: it deletes and recreates all questions, swags, and responses each time. 

new Swag_Question__c(
    Name = 'Favourite Device',
    Question_Text__c = 'Which device do you reach for first?',
    Order__c = 4,
    Active__c = true,
    Options__c = '[{"label":"Phone","score":3},{"label":"Tablet","score":2},{"label":"Laptop","score":1}]'
)

Run it with the Salesforce CLI:

sf apex run --file scripts/apex/seed_swag.apex
Adding or removing questions changes the possible score range, so revisit your swag bands (section 5) afterward to make sure every total still maps to a prize.

5. Configure the swags (prizes)

  1. Create/edit Swag records (in Salesforce or in the swags list of the seed script).
  2. Set Name, Description__c, an optional Emoji__c, and the band (Min_Score__c / Max_Score__c).
  3. Check Active__c so it can be awarded.

Example bands for a quiz whose totals range from 3 to 9:

SwagMinMax
Sticker & Decal Pack04
Wireless Earbuds56
Premium Hoodie79
Make the lowest band start at 0 and the top band end at (or above) the maximum possible score, so there is never a “no prize” gap. Bands should not overlap.

6. How answers are matched

When a customer replies, the engine maps their message to one of the current question’s options, trying in this order:

  1. A number — 1 picks the first option, 2 the second, and so on.
  2. Exact label — their text equals an option label (case-insensitive).
  3. Partial match — their text contains an option label, or vice-versa (e.g. “streaming” matches “Streaming & movies”).

If nothing matches, the agent gently re-asks the same question. The very first message that enters the quiz (e.g. “what swag can I win?”) is treated as entry, not a wrong answer, so it opens with Question 1 cleanly.

Keep option labels short and distinct so partial matching stays unambiguous. Avoid two options where one label is contained inside the other (e.g. “TV” and “Smart TV”).

7. Reset a customer’s attempt

Because there are no retakes, a customer who already finished will just be shown the swag they won. To let them (or you, during a demo) play again, delete their Swag_Response__c record.

Reset everyone (handy for demos) with scripts/apex/reset_swag_response.apex:

sf apex run --file scripts/apex/reset_swag_response.apex

Or reset a single customer in that script before running:

delete [SELECT Id FROM Swag_Response__c WHERE Contact__c = '003XXXXXXXXXXXXXXX'];

You can also just delete the record from the Swag Response list view in Salesforce.

9. Rules & gotchas

  • Only active records count. Uncheck Active__c to retire a question or swag without deleting it.
  • Order matters. Questions are asked by Order__c ascending; give each a distinct number.
  • Cover the full score range with swag bands — no gaps, no overlaps — so every total wins something.
  • Valid JSON only in Options__c (straight quotes, commas, no trailing comma).
  • Content changes are instant (just data). You only need to publish/activate the agent if you change the agent script itself, not when editing questions or swags.
  • One attempt per customer. Delete their Swag_Response__c to allow a replay.
